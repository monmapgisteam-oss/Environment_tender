# Гүйцэтгэлийн хянагч

Гэрээт ажлын үе шатны хугацааг хянаж, **шатлан мэдээллэх** (escalation) мэдэгдлийг автоматаар илгээдэг систем.

Өгөгдлийн эх сурвалж: `БАЙГАЛЬ ОРЧНЫ ХЯНАЛТЫН НЭГДСЭН СИСТЕМ — ТӨЛӨВЛӨГӨӨ (2026.06.15)`,
гэрээ **НХААГ/20260102029** (Нийслэлийн Байгаль Орчны Газар ← "Монмэп" ХХК).

## Үндсэн зарчим

Ажлын үе шат бүрийн эцсийн хугацааг **Х** гэвэл:

| Шат | Хэзээ | Хэн рүү |
|---|---|---|
| 1. Урьдчилсан сануулга | Х − 14 хоног | Гүйцэтгэгч компани (төслийн менежер, мэргэжилтэн) |
| 2. Эцсийн сануулга | Х − 3 хоног | Гүйцэтгэгч компани |
| 3. Хугацаа хэтэрсэн | Х + 1 хоног | **+ Захиалагчийн холбогдох хэлтсийн дарга** |
| 4. Ноцтой хоцролт | Х + 7 хоног | **+ Газрын дарга, Гүйцэтгэгчийн гүйцэтгэх захирал** |

Хугацаа дуусахаас өмнө тайлан ирсэн бол дараагийн шатны мэдэгдэл үүсэхгүй.
Хоногийн тоог `/tohirgoo` хуудсаас өөрчилнө. Мэдэгдэл амралтын өдөрт таарвал өмнөх ажлын өдөр рүү шилжинэ.

## Гүйцэтгэгч байгууллагууд

Систем нэг дор **20 гүйцэтгэгч компанийн** гэрээт ажлыг хянана. 1 дүгээрт "Монмэп" ХХК-ийн
НХААГ/20260102029 гэрээний бодит төлөвлөгөө (87 ажил × 5 үе шат), 2-20 дугаарт байгаль орчны
чиглэлийн бусад гэрээт ажлууд (агаарын чанар, ойжуулалт, усны шинжилгээ, хөрсний бохирдол,
хүлэмжийн хий, био олон янз байдал, нөхөн сэргээлт г.м.) — нийт **169 ажил, 763 хяналтын цэг**.

Компани бүр өөрийн гэрээний хугацаа, үе шаттай бөгөөд захиалагч талаас хариуцах хэлтэс
харгалзана. Мэдэгдэл нь тухайн компанийн төслийн менежер → хариуцах хэлтсийн дарга →
газрын дарга + тухайн компанийн гүйцэтгэх захирал гэсэн дарааллаар ахина.
Компанийн жагсаалт, хариуцагчдыг `lib/plan.ts`-ээс өөрчилнө.

## Хамрах хүрээ ("Монмэп" ХХК-ийн гэрээ)

- 7 нэгж (6 хэлтэс + үндсэн системийн модулиуд), нийт **87 ажил**
- Ажил бүр **5 үе шаттай** → **435 хяналтын цэг**
  1. Өгөгдлийн сан байгуулах — 2026.06.01–08.31
  2. Өгөгдлийн сан шинэчлэх — 2026.07.01–11.30
  3. Систем ашиглалтад оруулах — 2026.08.01–12.31
  4. Туршилтын орчинд байршуулах — 2027.01.01–01.31
  5. Засвар үйлчилгээ — 2027.02.01–02.14

## Ажиллуулах

```bash
npm install
npm run dev      # http://localhost:3000
npm run build && npm start
```

Анх ажиллуулахад төлөвлөгөөний өгөгдөл `data/db.json` файлд автоматаар үүснэ.

## Автомат ажиллагаа (cron)

Хөдөлгүүрийг өдөрт нэг удаа дуудна. Давхардсан дуудалт нэмэлт мэдэгдэл үүсгэхгүй (idempotent).

```bash
curl -X POST http://localhost:3000/api/escalate
curl "http://localhost:3000/api/escalate?date=2026-09-08"   # тодорхой огноогоор
```

- **Windows Task Scheduler**: өдөр бүр 09:00 цагт дээрх `curl` командыг ажиллуулна.
- **Vercel Cron** (`vercel.json`): `{ "crons": [{ "path": "/api/escalate", "schedule": "0 1 * * *" }] }`
- `CRON_SECRET` тохируулсан бол `Authorization: Bearer <secret>` толгой шаардана.

Хариу:

```json
{ "asOf": "2026-09-01", "reportsReceived": 11, "notificationsCreated": 74,
  "breakdown": { "final": 38, "level2": 36 } }
```

## Мэдэгдлийн суваг (`.env.local`)

| Хувьсагч | Утга |
|---|---|
| `NOTIFY_WEBHOOK_URL` | Мэдэгдэл бүрийг JSON-оор илгээх хаяг (Teams, Slack, дотоод API) |
| `RESEND_API_KEY` | И-мэйл илгээх түлхүүр ([resend.com](https://resend.com)) |
| `NOTIFY_FROM` / `NOTIFY_INBOX` | Илгээгч ба хүлээн авагчийн хаяг |
| `CRON_SECRET` | `/api/escalate` цэгийн хамгаалалт |

Аль нь ч тохируулаагүй үед мэдэгдэл системд бүртгэгдэж, серверийн лог руу бичигдэнэ.

## Дэлгэцүүд

| Зам | Агуулга |
|---|---|
| `/` | Хяналтын самбар — хугацаа хэтэрсний анхааруулга, үзүүлэлтүүд, гүйцэтгэлийн муруй (компаниар шүүх), хуанли, анхаарал шаардсан ажил, төлөвийн бүтэц, 20 компанийн хүснэгт |
| `/ajil` | 763 хяналтын цэгийн жагсаалт: хурдан шүүлтүүр (тоотой), компани/хэлтсээр шүүх, хайлт, CSV татах, дэлгэрэнгүй самбар |
| `/medegdel` | Илгээсэн мэдэгдэл — шатлалын тайлбар, түвшин/компаниар шүүх, хүлээн авагч, албан бичгийн эх бичвэр |
| `/tohirgoo` | Шатлалын хоног, нөхцөл, хүлээн авагчид, cron заавар |

**Хяналтын огноо** (дээд мөрөнд) — систем аль өдрөөр хянаж байгааг заана. Ирээдүйн огноо сонгож
шатлал хэрхэн ажиллахыг шалгаж болно. Бодит ашиглалтад `/tohirgoo` → "Заасан хяналтын огноогоор
ажиллах"-ыг унтраавал систем өнөөдрийн бодит огноогоор ажиллана.

Хуанлийн өдөр дээр дарахад хяналтын огноо тэр өдөр рүү шилжинэ. Улаан хүрээтэй өдөр = үе шатны
эцсийн хугацаа, шар цэг = тухайн өдөр мэдэгдэл илгээгдсэн. Доор нь хамгийн ойрын эцсийн хугацааны
анхааруулга гарна.

## Дизайн

Харанхуй, дарууссан өнгөтэй: бараг хар суурь, нимгэн хүрээтэй хавтгай карт, ганц өргөлт
өнгө (номин цэнхэр). Төлөвийн өнгө гурав — хөх ногоон (гүйцэтгэсэн), охра (сануулга),
тоосгон улаан (хугацаа хэтэрсэн); ноцтой хоцролт нь тэдгээрийн гэр бүлийн бүдэг ягаан.
Гэрэлтсэн, ханалт өндөртэй өнгө хэрэглээгүй.

**Нэг дэлгэц** — 1280px-ээс өргөн дэлгэцэд тойм самбар мөрүүддээ бүрэн багтаж,
хуудас өөрөө гүйхгүй. Урт жагсаалтууд зөвхөн карт дотроо гүйнэ. Нарийн дэлгэцэд
багануудаас доош бууж, хэвийн гүйлгэлт болно.

**Харанхуй / гэрэл горим** — дээд мөрний нар/сар товчоор сольж, сонголт хөтөч дээр
(`localStorage`) хадгалагдана. Анхдагч нь харанхуй. Бүх өнгө `globals.css`-ийн токеноор
удирдагддаг тул горим солиход бүх дэлгэц зэрэг өөрчлөгдөнө.

Фонт: Unbounded (гарчиг, том тоо), Manrope (бичвэр), JetBrains Mono (огноо, өгөгдөл) —
бүгд монгол кирилл (Ө, Ү) дэмжинэ. График бүр гадаад сангүй, SVG/CSS-ээр бичигдсэн
(`components/charts.tsx`).

## Үйлдвэрлэлд байршуулах (deploy)

Систем өгөгдлөө `data/db.json` файлд хадгалдаг тул **файлын систем нь тогтмол хадгалагддаг**
орчинд байршуулна: өөрийн сервер (VPS, дотоод сервер), Docker, эсвэл Windows Server.

```bash
npm ci
npm run build
npm start          # http://localhost:3000
```

**Docker:**

```bash
docker build -t hyanalt .
docker run -d --name hyanalt -p 3000:3000 -v hyanalt-data:/app/data --env-file .env hyanalt
```

**Тасралтгүй ажиллуулах:** PM2 (`pm2 start npm --name hyanalt -- start`), systemd, эсвэл Windows
үйлчилгээ болгон бүртгэнэ. Мэдэгдлийн хөдөлгүүрийг өдөр бүр дуудах хуваарь тавихаа бүү мартаарай
(дээрх "Автомат ажиллагаа" хэсэг).

**Vercel зэрэг serverless орчин:** тэнд бичигдсэн файл хадгалагддаггүй тул эхлээд `lib/db.ts`-ийн
`readDB`/`writeDB`-г жинхэнэ өгөгдлийн сангаар (Postgres, MongoDB) солино.

**Орчны хувьсагч:** `.env.example`-ийг `.env.local` (эсвэл `.env`) болгон хуулж бөглөнө.

## Бодит ашиглалтад шилжихэд

1. `/tohirgoo` → "Тайлан ирэхийг дуурайх"-ыг **унтраана**. Тайланг гараар эсвэл API-аар бүртгэнэ.
   (`lib/db.ts` доторх `demoArrival` функц болон `Milestone.demoArrivesAt` талбарыг устгаж болно.)
2. `lib/db.ts`-ийн `readDB`/`writeDB`-г жинхэнэ өгөгдлийн сангаар (Postgres, MongoDB) солино —
   бусад модуль өөрчлөгдөхгүй.
3. Хүлээн авагчдын и-мэйл хаягийг `lib/plan.ts`-д нэмж, `lib/notify.ts`-д бодит хаягаар илгээнэ.
4. Нэвтрэлт, эрхийн хяналт нэмнэ (хэлтсийн дарга зөвхөн өөрийн хэлтсийн мэдээлэл харах г.м.).
